# actup for VS Code

VS Code extension that integrates the `actup-lsp` language server for GitHub
Actions workflow files.

Provides diagnostics, code actions, hover info, and completion for `uses:` refs.

## Prerequisites

`actup-lsp` must be available on your system. Install from the repo root:

```sh
just install-actup-lsp
# cargo install --path crates/lsp
```

Or build without installing:

```sh
cargo build -p actup-lsp --release
```

## Install (user)

> Not yet published to the VS Code Marketplace.

Once published, search "actup" in the Extensions panel and install.

## Install (dev)

```bash
EXTENSION_DIR="$(git rev-parse --show-toplevel)/extensions/vscode"
bun --cwd="${EXTENSION_DIR}" install
bun --cwd="${EXTENSION_DIR}" run compile
```

Then launch VS Code with the extension loaded:

```bash
EXTENSION_DIR="$(git rev-parse --show-toplevel)/extensions/vscode"
code --extensionDevelopmentPath="${EXTENSION_DIR}"
```

Or press `F5` inside VS Code (with this folder open) to launch an Extension
Development Host.

## Configuration

All settings live under the `actup` namespace.

The web extension reads the repo config of each workspace folder: the first of
`actup.*`, `.actup.*`, `.config/actup.*` and `.github/actup.*`, trying the
extensions `toml`, `json`, `jsonc`, `yaml` and `yml` in that order, parsed as
the CLI parses it. Its `[policy]`, `[[overrides]]` and `scan.ignore` apply to
diagnostics and to Fix All in Workspace. An invalid config shows an error and
leaves the folder unchecked.

### `actup.server.path`

Absolute path to the `actup-lsp` binary. If unset, the extension searches
`PATH`.

<!--dprint-ignore-start-->

```jsonc
{
  "actup.server.path": "/home/you/projects/actup-v2/target/debug/actup-lsp"
}
```

<!--dprint-ignore-end-->

### `actup.server.extraArgs`

Extra arguments passed to `actup-lsp`. Default: `[]`.

### `actup-lsp.trace.server`

Trace LSP protocol messages. One of `"off"`, `"messages"`, `"verbose"`. Default:
`"off"`. Output goes to the "actup (trace)" output channel.

## Commands

| Command                   | Palette title                  |
| ------------------------- | ------------------------------ |
| `actup.fixAllInWorkspace` | actup: Fix All in Workspace    |
| `actup.restartServer`     | actup: Restart Language Server |

## Features

| Feature      | Description                                                                                       |
| ------------ | ------------------------------------------------------------------------------------------------- |
| Diagnostics  | Warning on outdated refs, error on unresolvable refs                                              |
| Code actions | Quick-fix to update single ref or all refs in file                                                |
| Hover        | Version status, README excerpt, action.yml summary                                                |
| Completion   | Action names from a built-in list and the default host's search; tag/version completion after `@` |

## Activation

The extension activates when a YAML file is opened. The LSP client only sends
documents matching these patterns to the server:

- `**/.github/**` (workflows, composite actions)
- `**/action.yml`, `**/action.yaml` (action repo roots)

Other YAML files are ignored.

## Extension structure

```tree
extensions/vscode/
  package.json       # Extension manifest, settings, commands
  tsconfig.json      # TypeScript config
  .vscodeignore      # Files excluded from packaging
  src/extension.ts   # LSP client entry point
  out/               # Compiled JS (generated by `npm run compile`)
```

## Development

### Build

```sh
bun run compile   # one-shot
bun run watch     # recompile on save
```

### Debug

Open this folder in VS Code and press `F5`. This launches an Extension
Development Host with the extension loaded. When running in debug mode,
`RUST_LOG=actup_lsp=debug` is set so the server produces verbose logs (visible
in the "actup" output channel).

### Package

```sh
bun run package   # produces actup-vscode-0.1.0.vsix
```

### How it works

The extension is a standard VS Code LSP client. It spawns `actup-lsp` as a child
process over stdio. All LSP logic lives in `crates/lsp/` -- the extension is
just the glue. Settings changes to `actup.server.*` auto-restart the language
server.
