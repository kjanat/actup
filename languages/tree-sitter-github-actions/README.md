# tree-sitter-github-actions

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://spdx.org/licenses/MIT.html)

Tree-sitter grammar for GitHub Actions workflow and composite-action files.

## Status

Pre-alpha. The grammar currently recognises full **YAML 1.2** and routes
`${{ … }}` expression text into the companion
[`tree-sitter-gh-actions-expressions`][gh-actions-expressions] grammar via
[`queries/injections.scm`](./queries/injections.scm). Actions-shaped node types
(`workflow`, `job`, `step`, `uses_ref`, …) are not yet first-class — consumers
see YAML mappings/sequences and have to walk them.

If you want a `(uses_ref owner: "actions" repo: "checkout" ref: "v4")` shaped
tree, that's planned, not built. See [`DESIGN.md`](../../DESIGN.md) at the
workspace root for direction.

## Layout

```tree
tree-sitter-github-actions/
├── grammar.js              # main YAML grammar (forked from ikatyang/tree-sitter-yaml)
├── tree-sitter.json        # package manifest
├── bindings/{c,go,java,node,python,rust,swift,zig}/
├── queries/
│   ├── highlights.scm      # syntax-highlight scopes
│   └── injections.scm      # ${{ … }} → gh_actions_expressions
├── schema/                 # plain-scalar typing sub-grammars (YAML 1.2 §10)
│   ├── core/               #   §10.3 Core Schema
│   └── json/               #   §10.2 JSON Schema
├── src/                    # generated parser + external scanner
│   ├── parser.c            # generated by `tree-sitter generate`
│   ├── scanner.c           # external scanner (forked yaml; hand-maintained)
│   └── schema.{core,json}.c # generated by `schema/update-schema.js`
├── test/corpus/            # tree-sitter test corpus
├── types/dsl-augment.d.ts  # local override for tree-sitter-cli 0.26 grammar() return type
└── README.md
```

## Build

From this directory:

```bash
bun install              # node binding (node-gyp-build)
bun run generate         # regen parser.c from grammar.js
bun run --filter 'tree-sitter-github-actions-*' build   # regen schema/{core,json}/src + emit src/schema.{core,json}.c
bun run test             # corpus tests (heavy on RAM — see notes)
```

Other bindings have their own toolchain (Cargo, Maven, Swift PM, Zig build, Go
modules); the same `src/parser.c` + `src/scanner.c` feeds all of them.

## Caveats

- Test suite memory: corpus runs may exceed ~10 GB during conflict resolution.
  Use [`scripts/ts-bounded.sh`](./scripts/ts-bounded.sh) (one level up) or split
  corpus when running locally.
- External scanner is a hard fork of `tree-sitter-yaml`'s scanner — see
  [`src/scanner.c`](./src/scanner.c). Upstream fixes don't propagate
  automatically.
- `schema/update-schema.js` regex-rewrites tree-sitter-cli's generated parser.c
  into a custom C state machine. Pin the cli version (`tree-sitter-cli@^0.26.8`
  in `package.json`) to avoid silent breakage.
