## Codebase Patterns

### Core Integration
- Use `actup_core::extract_uses_from_yaml()` for parsing (returns `Vec<UsesLocation>`)
- Use `actup_core::check_action()` for version resolution (returns `CheckResult`)
- Use `actup_core::provider::Registry` for multi-provider support
- Use `actup_core::Config` for policy/ignore settings

### Edit Patterns (from CLI)
- `PendingEdit::replace_ref(line, old_ref, new_ref)` for ref updates
- `FileEdits` for accumulating edits per file
- Preserve trailing newlines and formatting

### Diagnostic Computation Pattern
- `extract_uses_from_yaml(text)` -> `parse_uses(value)` -> `ActionRef` (skip `None` for local/docker)
- Deduplicate by `ActionRepoId`, batch fetch `version::Set` from cache then providers
- `check_action(action_ref, versions, config)` for synchronous check with pre-fetched data
- `UsesLocation.ref_range()` gives byte range after `@` in the raw line (0-indexed); `.line()` is 1-indexed
- `status_to_diagnostic()` for `CheckStatus` -> `Diagnostic` severity mapping

### tower-lsp-server Progress API
- `client.progress(token, title)` returns `Progress` builder (NOT a future)
- `.with_percentage(0)` → bounded; `.with_message(msg)` → initial message
- `.begin().await` → `OngoingProgress<Bounded, NotCancellable>`
- `ongoing.report_with_message(msg, pct).await` for updates
- `ongoing.finish_with_message(msg).await` to end
- Must call `client.create_work_done_progress(token).await` first (may fail if client doesn't support it)

### Workspace Commands
- `executeCommand` provider registered in `ServerCapabilities.execute_command_provider`
- Command handler in `LanguageServer::execute_command` dispatches by command string
- `client.apply_edit(workspace_edit).await` returns `ApplyWorkspaceEditResponse` with `.applied` bool
- Split large handler methods: keep trait impl thin, extract helpers to separate `impl` blocks

### Error Classification
- `Error::is_environment_error()` distinguishes user vs env errors
- User errors (NotFound, InvalidRef) -> Error severity
- Env errors (Network, RateLimit, Auth) -> Information severity + status message

### tower-lsp-server 0.23 Patterns
- Crate re-exports `ls_types` (not `lsp_types`) — use `tower_lsp_server::ls_types::*`
- Store `Client` handle in backend for async notifications
- `LspService::new(|client| Backend::new(client))` constructor pattern
- `Server::new(stdin, stdout, socket).serve(service).await` for stdio transport
- Use `DashMap` for concurrent document access
- Spawn background tasks with `tokio::spawn`
- Check client capabilities before using features
- `InitializeResult` has only 2 non-feature-gated fields: `capabilities` + `server_info`
- Tracing must write to stderr (stdout is the LSP transport)
- `Uri` has no `Display` — use `uri.as_str()` in tracing fields, not `%uri`
- `Uri::to_file_path()` returns `Option<Cow<'_, Path>>` — call `.into_owned()` for `PathBuf`
- `Uri::from_file_path(path)` returns `Option<Uri>` — useful in tests
- `Client` is `Clone` (backed by `Arc<ClientInner>`) — safe to clone into spawned tasks
- `Client::new` is `pub(super)` — can't construct in tests directly; use `LspService::new` or test components in isolation

### Code Action Pattern
- Use `params.context.diagnostics` (client-provided) as primary source for code actions — client already filters by cursor/selection
- Fall back to cached `DocumentState.diagnostics` when client sends empty context
- Embed structured data in `Diagnostic.data` as JSON (`DiagnosticData` enum) to carry target refs between diagnostic computation and code action generation
- `CodeAction.diagnostics` links back to triggering diagnostic(s) for editor UI integration
- `is_preferred: true` for Outdated quickfixes (auto-applicable), `false` for suggestions
- Fix-all source actions use ALL cached diagnostics (not cursor-scoped context), gated by `kind_allowed()` check against `context.only`
- `CodeActionKind` hierarchy: `source.fixAll` is parent of `source.fixAll.actup` — dot-separated prefix match, not substring
- Custom kinds as `const`: `CodeActionKind::new("source.fixAll.actup")` is const-capable

### Async Diagnostics Pattern
- Fields shared with spawned tasks must be `Arc`-wrapped: `DashMap`, `RwLock<Config>`, `RwLock<Option<Arc<Registry>>>`, etc.
- Per-document abort handles via `DashMap<Uri, AbortHandle>` for cancellation on re-edit
- Debounce via `tokio::time::sleep` at start of spawned task — aborted on cancellation = zero wasted work
- `Uri` doesn't impl `Copy` — clone before moving into async block, rebind inside
- `TextDocumentSyncOptions` (not `Kind`) required to declare `save` notification support
- `did_open` uses zero debounce (immediate), `did_change` uses 300ms, `did_save` uses zero

### Config Loading
- `Config::load(config_path, start_dir)` — layered (env > explicit > repo > user > defaults)
- `Config::discover(start_dir)` — never fails, convenience wrapper
- `config.policy_for(owner, repo)` / `config.should_ignore(owner, repo, ref_str)` for per-action queries
- Use `tokio::sync::RwLock<Config>` for async-safe interior mutability (future config reload)

### Provider Setup
- `build_registry(config)` mirrors CLI: collects `REGISTRATION` statics, resolves default host, registers providers
- `build_file_cache(config)` reads `config.cache.{enabled, path, ttl}` — shared dir with CLI
- `provider::Registry` stored as `Arc` in `LspBackend` for shared access from background tasks
- `FileCache` stored as `Arc` for same reason
- Token loaded via registration factory (`create_github_provider` reads `GITHUB_TOKEN` from env)
- `CachingProvider<P>` available in core but NOT used at registry level — designed for ad-hoc wrapping at call sites (diagnostic layer)
- `Box<dyn Provider>` does NOT impl `Provider`, so can't wrap registry entries directly

## Task - diagnostic-extraction

- Diagnostic `source` field is always "actup"; `code` field is "outdated"/"pinned"/"unresolvable"
- 11 new unit tests: severity mapping for all 5 statuses, extraction from YAML, ref range accuracy, local/docker skip, source field

- **Learnings:** `UsesLocation.ref_range()` returns byte offsets into the raw line (0-indexed), with `column` being 1-indexed — careful with the arithmetic; `check_action` is synchronous (needs pre-fetched `version::Set`), `check_action_remote` is async but fetches per-ref — batch fetching with dedup is more efficient for LSP; Rust 2024 let-chains (`if let ... && let ...`) simplify cache-hit checks
