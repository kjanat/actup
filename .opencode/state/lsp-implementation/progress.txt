## Codebase Patterns

### Core Integration
- Use `actup_core::extract_uses_from_yaml()` for parsing (returns `Vec<UsesLocation>`)
- Use `actup_core::check_action()` for version resolution (returns `CheckResult`)
- Use `actup_core::provider::Registry` for multi-provider support
- Use `actup_core::Config` for policy/ignore settings

### Edit Patterns (from CLI)
- `PendingEdit::replace_ref(line, old_ref, new_ref)` for ref updates
- `FileEdits` for accumulating edits per file
- Preserve trailing newlines and formatting

### Diagnostic Computation Pattern
- `extract_uses_from_yaml(text)` -> `parse_uses(value)` -> `ActionRef` (skip `None` for local/docker)
- Deduplicate by `ActionRepoId`, batch fetch `version::Set` from cache then providers
- `check_action(action_ref, versions, config)` for synchronous check with pre-fetched data
- `UsesLocation.ref_range()` gives byte range after `@` in the raw line (0-indexed); `.line()` is 1-indexed
- `status_to_diagnostic()` for `CheckStatus` -> `Diagnostic` severity mapping

### tower-lsp-server Progress API
- `client.progress(token, title)` returns `Progress` builder (NOT a future)
- `.with_percentage(0)` → bounded; `.with_message(msg)` → initial message
- `.with_cancel_button()` → shows cancel button (type-state: `Progress<B, Cancellable>`)
- `.begin().await` → `OngoingProgress<Bounded, Cancellable>` (or `NotCancellable`)
- `Cancellable` variant: `ongoing.report_with_message(msg, pct, Option<bool>).await` — third arg toggles cancel button
- `NotCancellable` variant: `ongoing.report_with_message(msg, pct).await` — only 2 args
- `ongoing.finish_with_message(msg).await` to end
- Must call `client.create_work_done_progress(token).await` first (may fail if client doesn't support it)
- `window/workDoneProgress/cancel` NOT implemented in tower-lsp-server 0.23 — use cooperative cancellation (e.g. `AtomicBool`)

### Workspace Commands
- `executeCommand` provider registered in `ServerCapabilities.execute_command_provider`
- Command handler in `LanguageServer::execute_command` dispatches by command string
- `client.apply_edit(workspace_edit).await` returns `ApplyWorkspaceEditResponse` with `.applied` bool
- Split large handler methods: keep trait impl thin, extract helpers to separate `impl` blocks

### Error Classification
- `Error::is_environment_error()` distinguishes user vs env errors
- User errors (NotFound, InvalidRef) -> Error severity
- Env errors (Network, RateLimit, Auth) -> Information severity + status message

### Completion Pattern
- `detect_completion_context()` parses cursor position on `uses:` line, returns `ActionName` or `VersionRef` context
- After `uses:` with partial/no text → suggest popular actions from hardcoded `POPULAR_ACTIONS` list
- After `owner/repo@` → fetch versions from provider (file cache first, then network), suggest semver tags + major tags
- Trigger character: `@` (registered in `CompletionOptions`)
- `CompletionItem.insert_text` for action names includes `owner/repo@defaultRef` for full insertion
- `CompletionItem.label_details.detail` shows short SHA for version items
- `CompletionList.is_incomplete = true` for version completions (network may change), `false` for action names
- LSP `character` position is 0-based column of cursor; text typed = line content from content_col through cursor_col (inclusive)
- Only count spaces/tabs (not newlines) as whitespace between `uses:` and value — `trim_start()` eats newlines which breaks empty-value detection
- Quote stripping: detect leading `"` or `'`, offset content_col by 1, strip trailing quote from value before analysis

### Error Notification Pattern
- `ErrorCategory::from_core_error()` classifies `CoreError` into notification categories
- `ErrorDeduplicator` (session-scoped `Mutex<HashSet>`) prevents repeat notifications
- `DiagnosticErrors` collects per-run errors, deduped by category within a single run
- `notify_errors()` dispatches: RateLimit/Auth/Forbidden → `showMessage`, Network/ProviderNotFound → `logMessage`
- Environment error diagnostics use `"(check failed: reason)"` format; user errors use direct format
- Reset deduplication on config reload so persistent errors re-notify after user fixes config
- `compute_diagnostics` returns `DiagnosticResult { diagnostics, errors }` — caller handles notifications

### Config Watching Pattern
- Dynamic watcher registration via `client.register_capability` in `initialized` (not `initialize`)
- Gate on `caps.workspace.did_change_watched_files.dynamic_registration == Some(true)`
- `Registration { id, method: "workspace/didChangeWatchedFiles", register_options: serde_json::to_value(opts) }`
- `DidChangeWatchedFilesRegistrationOptions { watchers: Vec<FileSystemWatcher> }` with `GlobPattern::String(pattern)`
- `is_actup_config_path` checks URI filename component (after last `/`) — covers `actup.toml` and `.actup.toml`
- Policy comparison on reload: compare `update_policy`, `ref_style`, `branch_policy`, `allow_prerelease`, `ignore`, `action_overrides`
- `ActionOverride` lacks `PartialEq` — compare via JSON serialization
- On policy change: clear cached diagnostics, re-schedule all open documents with zero debounce
- Workspace folder changes: update `workspace_root`, then reload config

### Hover Pattern
- `find_action_at_position()` matches cursor to `uses:` value via `extract_uses_from_yaml` + column range check
- `value_range()` returns `Range` (exclusive end) — use `>=` for end boundary, `<` for start
- `Provider::get_action_yml` / `get_readme` NOT cached by `CachingProvider` — cache in LSP via `DashMap<ActionMetaCacheKey, Arc<CachedActionMeta>>`
- `ActionMetaCacheKey` keyed by (owner, repo, ref_str, host) — different refs get different cache entries
- `ActionYml` accessors: `.name()`, `.description()`, `.author()`, `.inputs()`, `.runs()`; `ActionInput.deprecation_message()` for deprecated input warnings

### tower-lsp-server 0.23 Patterns
- Crate re-exports `ls_types` (not `lsp_types`) — use `tower_lsp_server::ls_types::*`
- Store `Client` handle in backend for async notifications
- `LspService::new(|client| Backend::new(client))` constructor pattern
- `Server::new(stdin, stdout, socket).serve(service).await` for stdio transport
- Use `DashMap` for concurrent document access
- Spawn background tasks with `tokio::spawn`
- Check client capabilities before using features
- `InitializeResult` has only 2 non-feature-gated fields: `capabilities` + `server_info`
- Tracing must write to stderr (stdout is the LSP transport)
- `Uri` has no `Display` — use `uri.as_str()` in tracing fields, not `%uri`
- `Uri::to_file_path()` returns `Option<Cow<'_, Path>>` — call `.into_owned()` for `PathBuf`
- `Uri::from_file_path(path)` returns `Option<Uri>` — useful in tests
- `Client` is `Clone` (backed by `Arc<ClientInner>`) — safe to clone into spawned tasks
- `Client::new` is `pub(super)` — can't construct in tests directly; use `LspService::new` or test components in isolation

### Code Action Pattern
- Use `params.context.diagnostics` (client-provided) as primary source for code actions — client already filters by cursor/selection
- Fall back to cached `DocumentState.diagnostics` when client sends empty context
- Embed structured data in `Diagnostic.data` as JSON (`DiagnosticData` enum) to carry target refs between diagnostic computation and code action generation
- `CodeAction.diagnostics` links back to triggering diagnostic(s) for editor UI integration
- `is_preferred: true` for Outdated quickfixes (auto-applicable), `false` for suggestions
- Fix-all source actions use ALL cached diagnostics (not cursor-scoped context), gated by `kind_allowed()` check against `context.only`
- `CodeActionKind` hierarchy: `source.fixAll` is parent of `source.fixAll.actup` — dot-separated prefix match, not substring
- Custom kinds as `const`: `CodeActionKind::new("source.fixAll.actup")` is const-capable

### Async Diagnostics Pattern
- Fields shared with spawned tasks must be `Arc`-wrapped: `DashMap`, `RwLock<Config>`, `RwLock<Option<Arc<Registry>>>`, etc.
- Per-document abort handles via `DashMap<Uri, AbortHandle>` for cancellation on re-edit
- Debounce via `tokio::time::sleep` at start of spawned task — aborted on cancellation = zero wasted work
- `Uri` doesn't impl `Copy` — clone before moving into async block, rebind inside
- `TextDocumentSyncOptions` (not `Kind`) required to declare `save` notification support
- `did_open` uses zero debounce (immediate), `did_change` uses 300ms, `did_save` uses zero

### Config Loading
- `Config::load(config_path, start_dir)` — layered (env > explicit > repo > user > defaults)
- `Config::discover(start_dir)` — never fails, convenience wrapper
- `config.policy_for(owner, repo)` / `config.should_ignore(owner, repo, ref_str)` for per-action queries
- Use `tokio::sync::RwLock<Config>` for async-safe interior mutability (future config reload)

### Provider Setup
- `build_registry(config)` mirrors CLI: collects `REGISTRATION` statics, resolves default host, registers providers
- `build_file_cache(config)` reads `config.cache.{enabled, path, ttl}` — shared dir with CLI
- `provider::Registry` stored as `Arc` in `LspBackend` for shared access from background tasks
- `FileCache` stored as `Arc` for same reason
- Token loaded via registration factory (`create_github_provider` reads `GITHUB_TOKEN` from env)
- `CachingProvider<P>` available in core but NOT used at registry level — designed for ad-hoc wrapping at call sites (diagnostic layer)
- `Box<dyn Provider>` does NOT impl `Provider`, so can't wrap registry entries directly

## Task - completion-provider

- Created `crates/lsp/src/completion.rs`: completion provider for `uses:` references
- Two completion contexts detected via `detect_completion_context()`:
  - `ActionName`: after `uses:` with no or partial text — suggests from hardcoded `POPULAR_ACTIONS` list (13 well-known actions: checkout, setup-node, cache, etc.)
  - `VersionRef`: after `owner/repo@` — fetches versions from provider registry (file cache first, then network)
- `POPULAR_ACTIONS` static list: `actions/checkout`, `actions/setup-node`, `actions/setup-python`, `actions/cache`, `actions/upload-artifact`, `actions/download-artifact`, `actions/setup-go`, `actions/setup-java`, `actions/github-script`, `actions/setup-dotnet`, `docker/build-push-action`, `docker/login-action`, `docker/setup-buildx-action`
- `action_completions()`: filters by prefix (case-insensitive), sets `insert_text` to `owner/repo@defaultRef`, adds GitHub link in documentation, sort order preserves popularity
- `version_completions()`: fetches `version::Set` from provider, suggests latest (preselected), major tags (newest first), and semver tags (newest first, capped at 20), with short SHA in `label_details`
- `CompletionItem.kind`: `MODULE` for actions, `VALUE` for versions
- Trigger character: `@` (registered in `CompletionOptions` in `ServerCapabilities`)
- `completion` handler on `LanguageServer`: clones doc text, snapshots registry/cache, delegates to `compute_completions`; early-exits if no `uses:` keyword or no registry
- `CompletionList.is_incomplete`: `false` for action names (static list), `true` for version refs (network-dependent)
- 27 new tests: context detection (empty, partial name, version ref, empty version prefix, quoted values, single-quoted, multiline, non-uses line, cursor before value), `parse_owner_repo` (simple, subpath, invalid cases), `action_completions` (all, filtered, case-insensitive, partial owner, insert text, documentation, sort order, no match), `version_completion_item` (preselect, sort order, SHA label detail), popular actions validation
- Files: `crates/lsp/src/completion.rs` (new), `crates/lsp/src/backend.rs`, `crates/lsp/src/main.rs`
- **Learnings:** LSP `character` is 0-based column of cursor position; for completion context, include the character AT cursor_col (use `..=offset`); only skip spaces/tabs (not newlines) after `uses:` colon to avoid breaking empty-value detection when cursor is right after `uses: `; `trim_start()` eats newlines — use manual byte counting for YAML value whitespace; `CompletionOptions` has `trigger_characters` (not `trigger_chars`); `version::Set::major_tags()` returns `HashMap<u32, Arc<Info>>` — sort by key descending for newest-first display
