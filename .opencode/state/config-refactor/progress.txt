# Progress Log

PRD: config-refactor
Started: 2026-02-18

## Codebase Patterns

- Config types live in `crates/core/src/config/mod.rs`, re-exported via `crates/core/src/lib.rs`
- Crate dir is `crates/core/` (not `crates/actup-core/` as AGENTS.md suggests)
- Enums use `#[serde(rename_all = "lowercase")]` for TOML/JSON serialization
- Tests in same file via `#[cfg(test)] mod tests`, use `#[allow(clippy::unwrap_used)]`
- `serde_json` + `toml` available as dev-deps for round-trip tests
- `deny_unknown_fields` used on `FetchSettings` and `HostConfig`
- `Hash` derive needed on `HostKind` for use as `HashMap` key in later tasks
- Registration types in `config/registration.rs` submodule, re-exported from `lib.rs`
- `Registration` uses `fn` pointer fields (`infer_api_base`, `create`); needs manual `Debug` impl with `finish_non_exhaustive()`
- CLI `build_registry()` in `crates/actup/src/main.rs` — main consumer of config provider fields
- Config display in `crates/actup/src/commands/config.rs` — human-readable config output
- Example configs in `examples/` — must be kept in sync with config struct changes
- `Config` has `#[serde(default)]` on the struct, so all new fields must either have `Default` or be `Option`

## Task - host-config

- Added `HostConfig` struct with all-`Option` fields: `kind`, `api_base`, `token_env`, `api_mode`, `max_tags_per_repo`
- `#[serde(deny_unknown_fields)]` for typo protection, NO `#[serde(default)]` since fields are explicit overrides

- Re-exported from `actup_core::HostConfig`
- Files changed: `crates/core/src/config/mod.rs`, `crates/core/src/lib.rs`
- **Learnings:** `HostConfig` intentionally has no `Default` impl — all fields are `Option` overrides, not defaults. `deny_unknown_fields` without `default` means deserialization requires no extra fields but doesn't fill missing ones

## Task - registration-types

- Added `config/registration.rs` submodule with `Preset`, `Capabilities`, `ProviderConfig`, `Registration` types
- `Preset`: `&'static str` fields (host, api_base, token_env) — zero-cost for static registration
- `Capabilities`: `supports_graphql` + `supports_rest` bools for api_mode validation
- `ProviderConfig`: fully-resolved host config (all required fields non-Option) — passed to `Registration::create`
- `Registration`: kind, presets slice, default_token_env, `infer_api_base` fn, capabilities, `create` fn
- Custom `Debug` impl on `Registration` (fn pointers not Debug-derivable), uses `finish_non_exhaustive()`
- Re-exported from `actup_core::{Capabilities, Preset, ProviderConfig, Registration}`
- 9 tests: preset/capabilities/provider_config construction, registration construction + infer_api_base + create + debug + multiple/no presets
- Files changed: `crates/core/src/config/registration.rs` (new), `crates/core/src/config/mod.rs`, `crates/core/src/lib.rs`
- **Learnings:** `fn` pointers don't implement `Debug`, so `Registration` needs a manual `Debug` impl; `finish_non_exhaustive()` is cleaner than omitting fn fields. Separate submodule keeps `config/mod.rs` from growing unboundedly
