## Codebase Patterns
- Provider trait in `crates/core/src/provider.rs` — uses `BoxFuture` (cfg-gated Send on native, !Send on wasm32)
- All providers use `reqwest` + `rustls`, retry via `tokio::time::sleep`
- `CachingProvider` wraps `Provider` with `AsyncRwLock` (tokio on native, std on wasm32); tokio is cfg-gated dep
- `actup-providers` (shared) is already WASM-compatible (pure computation)
- Zed extension is separate workspace (wasip2 cdylib conflicts with root workspace)
- SystemTime::now() in 3 places: cache.rs:34, version.rs:389, graphql.rs:200
- serde `rc` feature already enabled — Arc<T> serializes transparently
- version::Set already derives Serialize/Deserialize
- wasm extern block `Result<JsValue, JsValue>` must use `std::result::Result` (not actup_core::Result which only takes 1 type param)
- `default-members` in root Cargo.toml excludes actup-wasm from native builds (JsValue is !Send/!Sync)
- JsProvider → Provider adapter: decompose ActionRepoId into (host, owner, repo) for JS boundary; JS returns camelCase objects

- npm package subpath exports: `"./provider"` in package.json exports map for `src/provider.ts`, also re-exported from main entry
- GitHub REST API patterns: `/repos/{o}/{r}/tags?per_page=N` (paginated via Link header), `/repos/{o}/{r}/git/ref/tags/{ref}` (resolve tag → SHA), `/repos/{o}/{r}/branches/{branch}` (fallback for branch refs), `/repos/{o}/{r}/contents/{path}?ref=R` (base64-encoded file content)
- Mock fetch testing pattern: override `globalThis.fetch` with route-matching mock, restore after each test — no deps needed
- Zed extension pattern: bypass async `Provider` trait, use Zed's sync `fetch()` directly → `version::Set` → `check_action()` (sync)
- Zed worktree: no directory listing — probe known workflow filenames (ci.yml, build.yml, etc.)
- Zed HTTP: host-proxied `zed:extension/http-client`, not WASI HTTP; synchronous, no URL restrictions

## Architecture Decisions
- MaybeSend trait alias (not feature flags, not separate trait)
- Clock trait injection (not platform crates)
- Eliminate FS from WASM surface (host provides content)
- Skip WASM LSP — VS Code web calls WASM directly (Biome/Ruff pattern)
- actup-wasm as workspace member (not separate like Zed)
- npm: unscoped `actup-wasm` (not @actup/wasm)
- wasm-opt -O2 stripped, .js.map shipped, no DWARF

- npm package pattern: `packages/actup-wasm/` uses `--target web` wasm-pack output in `wasm/` subdir; TS wrapper in `src/` compiled to `dist/`; `initSync({ module })` for Node, `init()` for browser
- Clock trait pattern: `_with_clock` variants keep existing API stable; `&dyn Clock` param, not generic
- `Clock: fmt::Debug + MaybeSend + MaybeSync` — Debug required for structs that derive Debug (e.g. GraphQLClient)
- `compat.rs` pattern: `MaybeSend`, `MaybeSync` trait aliases + `BoxFuture` type alias — all cfg-gated on `target_arch = "wasm32"`
- CLI/LSP `file_cache.rs` still uses raw `Pin<Box<dyn Future<...> + Send>>` — fine since native-only binaries
- WASM exports use `serde-wasm-bindgen` (not `serde_json` string round-trip) — native JS objects cross boundary
- `wasm-pack build crates/wasm --target nodejs --out-dir ../../target/wasm-pkg` for Node.js testing
